# Recall 提前终止预设计

> 状态：未来预设计，尚未实现，不进入一期。首版只讨论显式 onFail:stop，不预先增加完整护栏／规则引擎。
>
> 提前停止改变剩余轮次是否执行，不改变断言的 boolean 或 score；默认分值仍为 `{hit: 1, miss: -1}`。

## 1. 目的与非目标

当某轮已明确不满足必需前提时，避免继续发送没有意义的后续任务。断言仅计分与断言影响控制流是两个独立选择。

首版不提供 onPass、onAbsent、自动重试、恢复提示词、成功判据生成或任意停止表达式。

## 2. 作者形状

```yaml
# PRE-DESIGN ONLY
turns:
  - send: 先读取规则并确认前提
    expect:
      judge:
        ready:
          rubric: 是否明确具备继续执行的前提
          score:
            hit: 0
    onFail: stop

  - send: 执行任务

expect:
  judge:
    final_state:
      rubric: 最后一次回答是否如实说明当前状态
```

省略 onFail 时，内容失败只影响结果，后续轮次仍执行。hit=0 时默认 miss=-1，因此 ready 失败扣 1，并因显式 onFail 停止，而不是因为负分本身停止。

## 3. 字段与触发条件

- onFail 只允许出现在 turn 上，首版唯一值为 stop。
- 配置该字段的 turn 必须至少有一项 boolean 断言；仅有分类项不能触发它。
- 当前 turn 的所有机械／AI 断言完成后，只要有一项明确 pass=false，就触发停止。
- 不以本轮总分、分数正负、某个分类类别或 Judge reason 文本推断失败。
- 显式 miss=0 的失败仍触发；其他细项正分也不抵消它。
- 不在一个批量 Judge 内遇到首项 false 就丢弃剩余裁定；保留本轮完整证据后停止后续 send。

非法值、错误位置或缺少断言都在主 Driver 前拒绝。

## 4. 与条件分支、最终评价的顺序

```text
主执行／评测发生错误 → 错误终止
否则完成当前 turn 的所有判断与计分
若 onFail:stop 命中 → 内容失败停止整个 case，不进入后续子分支或外层公共后续
否则 → 顺序执行下一节点；条件分支只执行所选子序列
```

- 触发 onFail 后，不再执行整个 case 的剩余 turn，包括当前子序列、尚未进入的嵌套分支和各层外部公共后续；不再调用它们的 Judge。
- 当前轮完成且有可用文本时，case.expect 仍运行，评价最后一次实际输出。
- case 最终评价即使通过，也不能把已触发 onFail 的失败改成成功。
- 当前轮基础设施／评测错误时不继续发起 case 最终 Judge，直接保留错误与清理，避免把不完整执行当正常终点。
- 分支子序列自然结束只返回外层继续，不是提前停止；首版不提供分支局部 stop 或 goto。

配合 [条件分支](./recall-conditional-branching-pre-design.md) 使用时，onFail 在继续树遍历前生效，不允许进入其他分支或公共后续把当前失败藏掉。

## 5. 分数与结果

- 已执行且有效的各断言按自己的 score 计分，默认 1／-1。
- 后续未执行轮次标记 skipped，不产生伪造通过、未命中或扣分。
- case 最终断言若运行，其结果与分值也保留。
- 因 onFail 停止时，最终 case 未通过；总分单独报告，不靠分数反推停止原因。
- 已因 onFail 停止时，不执行 [Decision](../recall/recall-judge-dsl.md#decision-分数验收政策) 放行计算；报告政策未执行，skipped 仍按上文处理。
- 不引入缺席映射、分母排除或剩余轮次自动补分。

## 6. 报告与退出语义

报告应区分：

| 结束情况                         | 结果与退出                                       |
| -------------------------------- | ------------------------------------------------ |
| 顺序与分支流程自然完成           | 按实际适用断言判断，内容结果 CLI=0。             |
| onFail:stop                      | 内容失败，CLI=0；保留失败 turn、细项与停止原因。 |
| 调用、超时、裁定／结果缺失等错误 | 基础设施／评测错误，CLI=1，不生成正常通过结论。  |
| onFail DSL 非法                  | 定义错误，CLI=2，主 Driver 前拒绝。              |

至少记录 terminal turn 的结构位置、触发的失败项、已执行路径、skipped 轮次、case 最终评价是否运行、总分与清理结果。不把正常分支返回、内容失败停止和错误终止混成一个 completed 布尔。

这些是报告语义草案，不预先发布新的公共枚举。

## 7. 取消与清理

停止后不再启动后续主执行或 Judge；已启动的当前评价按其正常结束或错误路径清理。关闭主 Driver／sandbox 仍须在 finally 兑现，不能因为“提前结束”跳过 cleanup。

外部取消、超时与 onFail 不是同一种原因。取消时按既有 abort 规则关闭挂起或迟到的 Driver，不把取消解释成内容未通过。

## 8. 验收与未验证范围

未来零 token 测试覆盖：默认继续、显式停止、正总分仍停止、miss=0 仍停止、分类不触发、本轮所有细项保留、嵌套 onFail 停止整个 case 及外层后续、case 最终评价时机、后续无调用、skipped 不计分及 finally 清理。

本文没有执行原型、真实调用或验证停止后的宿主行为。成功早停、分类驱动停止与自动恢复留待明确需求，不作为本首版的隐藏扩展。
