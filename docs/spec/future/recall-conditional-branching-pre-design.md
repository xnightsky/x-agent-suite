# Recall 条件分支预设计

> 状态：未来预设计，尚未实现，不进入一期。作者使用结构化条件树：子步骤嵌在所选分支中，结束后自然继续外层流程。
>
> 不依赖 Decision；条件场景的可比性是规则一致，不要求所有运行轨迹相同。JSON／YAML 是载体，控制流由嵌套结构表达，不由全局跳转标签表达。
>
> 未决边界：上述可比性主张与现行 [Scenario DSL](../scenario-dsl.md#可比性轴) 的主动分支禁令尚未统一。归档不代表改变现行原则；实施前必须先裁决适用边界并更新规格。

## 1. 目的与设计选择

根据 [分类](./recall-classification-pre-design.md) 或 boolean 判断，执行作者预先声明的一组步骤。模型只产结果，不生成下一步。

作者层采用“顺序 + 条件分支”，不提供 next／goto，也不同时保留另一套跳表语法：

- 条件与对应步骤放在一起，修改分支不必追踪远处跳转。
- 分支完成后自然返回包含它的序列，不需要手写 stop 防止串入相邻分支。
- 公共后续放在分支节点之后，不必复制或命名为汇合目标。
- 内部可以递归解释或编译为跳表／状态机，但编译结果不是作者契约。

一期仍是线性 turns。以下树形节点是未来扩展，不能把示例当作当前 schema 已支持。

## 2. 作者形状

```yaml
# PRE-DESIGN ONLY
turns:
  - id: route
    send: 判断当前信息是否足够回答
    expect:
      judge:
        route:
          choices:
            answer: 已经可以回答
            clarify: 需要补充信息
          else: other

  - branch:
      cases:
        - when: turn.route.judge.route == answer
          turns:
            - send: 给出最终答案
        - when: turn.route.judge.route == clarify
          turns:
            - send: 请求补充缺失信息
      else: []

  - send: 汇总本次处理状态
```

answer、clarify 的步骤是各自分支的子节点，不是全局标签。other 走空 else，然后继续公共后续；既不停止 case，也不自动判通过。

## 3. 节点与字段

根 turns 和每个分支内的 turns 都是顺序步骤数组，元素恰好是以下一种：

| 节点      | 形状与规则                                                    |
| --------- | ------------------------------------------------------------- |
| 普通 turn | 延续 send、expect、可选 id／onFail 等轮次字段。               |
| 分支节点  | 恰含 branch；不能与 send、expect、id、onFail 等轮次字段混用。 |

branch 对象只有：

| 字段          | 规则                                             |
| ------------- | ------------------------------------------------ |
| cases         | 必填非空有序数组。                               |
| cases[].when  | 必填的简单相等条件。                             |
| cases[].turns | 必填步骤数组，可以为空，可继续内嵌 branch。      |
| else          | 必填步骤数组，可以为空；所有条件均不命中时执行。 |

每个 cases 项恰含 when 与 turns。根 turns 保持非空；子数组允许为空，表示该分支无需额外动作。未知字段、错误类型、缺 else 或混用节点形状都是定义错误。

## 4. 条件与作用域

when 只接受：

```text
turn.<id>.judge.<name> == <类别名或 true/false>
turn.<id>.outcome.<name> == <true/false>
```

- Judge 引用可以是分类或 boolean，按来源类型解释右值；分类精确匹配声明类别，boolean 只接受 true／false。
- 条件显式引用来源 turn，不使用含义随路径变化的“最近一轮”简称。
- 条件只读取在当前序列中、进入该分支节点前已经完成的结果；父序列中可见的既有结果向子分支继承。
- 分支内部新增结果可供本分支后续步骤和嵌套分支读取，但不向兄弟分支或外层公共后续导出。
- 未知来源、未来来源、越作用域引用或类型不符在主 Driver 前拒绝；不能依赖“本次也许会走到那个 turn”。
- 运行时应有结果缺失或无效是评测错误，不使用 else 恢复。
- 不读取分数、case 最终裁定或 Decision，不支持 &&、||、!、数值比较、插值、函数或自由脚本。

被引用的 turn 需要稳定 id，所有已声明 turn id 在同一 case 内唯一，不含点号、空白或等号；它仅用于证据身份和结果引用，不是可跳转目标。branch 本身不需要作者命名。

结果作用域只限制条件可读取什么，不删除报告中的逐轮证据。

## 5. 嵌套与自然汇合

```yaml
# PRE-DESIGN ONLY
turns:
  - id: prepare
    send: 确认执行前提
    expect:
      judge:
        ready:
          rubric: 是否具备执行前提

  - branch:
      cases:
        - when: turn.prepare.judge.ready == true
          turns:
            - id: answer
              send: 给出答案并说明是否需要核对
              expect:
                judge:
                  needs_check:
                    choices:
                      yes: 需要额外核对
                    else: no
            - branch:
                cases:
                  - when: turn.answer.judge.needs_check == yes
                    turns:
                      - send: 只进行一次额外核对
                else: []
      else:
        - send: 说明前提不足

  - send: 汇总本次处理状态
```

内层分支结束后返回当前子序列；外层分支结束后统一执行汇总。没有循环、回跳、跨分支跳转或节点引用复用；树中的每个普通 turn 在单次执行中至多执行一次。

嵌套层数增加会影响可读性，复杂场景宜拆成多个 case；首版不为此增加函数、片段引用或另一套图 DSL。

## 6. 固定执行顺序

```text
顺序处理当前序列：
  普通 turn → 发送、收集输出、完成断言／分类
              → 错误则终止；onFail:stop 命中则停止整个 case
  branch    → 按 cases 顺序读取条件，执行第一个命中的 turns
              → 均不命中则执行 else
              → 子序列正常完成后，继续当前序列下一节点
```

- 同时有多个条件成立时，只执行第一个，不合并子步骤。
- 未选择的分支不发送输入、不调用 Judge，子断言不生成 pass／miss 或分数。
- 普通内容失败默认继续；只有显式 onFail:stop 才阻止剩余所有分支与外层公共后续。
- 条件 false 只表示不选择该分支；如果它来自 boolean 断言，原断言失败仍保留，不会因合法进入 else 而洗成通过。
- branch 不是新的主 Driver 会话；所选子步骤和公共后续沿用同一次 case 执行。

## 7. 计分、结束与错误

机械与 boolean AI 断言的 score 可省略，默认 1／-1。只汇总实际路径上应执行的断言；分类本身不计分，分支命中也不额外加减分。

树执行完是正常结束，不代表自动通过。case 最终 Judge 只评价最后一个实际执行的 turn 文本；如果有公共后续，它也是实际路径的一部分。

[提前终止](./recall-early-termination-pre-design.md) 的 onFail:stop 始终停止整个 case，不是退出当前分支；仍按既有草案运行 case 最终评价，且不能抹掉已确认的失败终止。评测错误则按错误路径停止与清理，不继续求值或执行 else。

| 场景                                   | 语义                                |
| -------------------------------------- | ----------------------------------- |
| 合法路径执行完、断言通过或内容失败     | 按实际断言判断，内容结果 CLI=0。    |
| 必需结果缺失、无效或调用失败           | 评测错误，CLI=1，不选择兜底分支。   |
| 节点形状、条件、类型、名称或作用域非法 | 定义错误，CLI=2，主 Driver 前拒绝。 |

## 8. 报告、覆盖与实现接缝

报告至少保留分支在作者树中的结构位置、条件输入、首命中项／else、实际 turn 顺序、未选择子树、最终评价位置与停止原因。不以编译后的指令号取代作者可定位的结构位置。

重要分支通过多个 case 构造前提覆盖，同一前提的方差通过 repeat 观察；不自动穷举、补跑或新增覆盖率计分门禁。

普通线性 turns 的含义保持不变。现有 scenario-dsl 的静态限制，以及树形节点如何编译到既有运行接缝，应在未来正式规格和计划中同步确认；不以此要求一期实现任意图执行器。

## 9. 验收与未验证范围

未来零 token 测试覆盖：

- 分类各路径、boolean 条件、首命中顺序、必填空 else 与空命中子序列。
- 嵌套返回、公共后续只执行一次、不误执行相邻分支、线性场景兼容。
- 父结果继承、分支局部结果、越作用域／未来引用拒绝与全 case id 唯一。
- 缺结果不走 else，未选择子树零调用、不计分。
- 默认继续、onFail 停止整个 case、外层后续被停止、最终评价时机及清理。
- 两个 YAML 示例在固定脚本结果下的路径、逐项得分和最终实际文本。

本文未实现运行接缝、生产执行器或真实模型路径实验；文档算例验证不等于宿主集成验证。相关职责继续见 [轮次级断言](./recall-turn-assertion-pre-design.md) 与 [提前终止](./recall-early-termination-pre-design.md)。
